# Conciliación de estados de tarjetas recibidos por N8N

**Solicitud y especificación antes del código:** 2026-11-01 America/Santiago. El titular autoriza un nuevo flujo N8N al recibir desde `enviodigital@bancochile.cl` el asunto `Estado de Cuenta Tarjeta de Crédito`, descargar sus PDF protegidos y conciliarlos contra los cargos existentes. Los dos ejemplos son PDF nativos con secciones nacional e internacional; no requieren OCR ni IA. Contraseña exclusivamente en configuración privada del servidor, jamás en repo, workflow exportado, logs o argumentos de proceso.

Esta entrega automatiza lectura y contraste, con resultados visibles. **No inserta, actualiza ni elimina gastos, cuotas, clasificaciones, pagos o saldos financieros.** Faltantes, contradicciones y diferencias se presentan para revisión. No modifica los flujos bancarios existentes. Es una ampliación específica del diseño de Epic14: PDF facturado por correo, independiente del importador Excel no implementado. No reutilizar importadores que ejecutan DDL/deduplicación por parecido.

## Interfaces coordinadas

Extracción `backend/services/cardStatements/extract_statement.py`: JSON stdin `{pdfBase64,password,filename}`, JSON stdout `{version:1,network,mainCardLastFour,statementDate,period:{since,until},dueDate,sections:[{scope,currency,totals,validation:{valid,issues},items:[]}],validation:{valid,issues}}`. Cada item: `{rowKey,page,date,description,reference,cardLastFour,kind,currency,amount,operationAmount,installmentNumber,installmentTotal}`; amount es valor mensual firmado, CLP entero/USD decimal dos posiciones. No emitir nombres/direcciones/PAN ni texto bruto. Errores solo código seguro en stderr/JSON; sin traceback privado.

Backend: `cardStatementService` factory `{db,extractor,env,now}` con `ingest({buffer,filename,messageId,attachmentId,from,subject})`, `list(actorId,{year,month})`, `detail(actorId,id)`. Nuevo router /api/card-statements. Extractor Node separado usa Python path privado/inyección en pruebas. Persistencia almacena DTO normalizado y fuentes mínimas; matching se calcula contra fuentes actuales. List devuelve `{items:[{id,network,statementDate,period,dueDate,validation,status,sections:[{scope,currency,totals,counts:{matched,missing,review,informational}}]}]}`; detail mismo resumen con items por sección y hallazgos `{status,reason,candidateCount,sourceType,sourceId,periodMismatch}`. status general ready/review/invalid. No rutas de escritura financiera.

Plantilla N8N usa Gmail Trigger→descargar mensaje/adjuntos→validar remitente/asunto y separar PDF→HTTP multipart→resumen. Password no viaja por N8N. Se admite una rama manual de prueba acotada al mismo remitente/asunto que no marca mensajes y usa la misma idempotencia.
