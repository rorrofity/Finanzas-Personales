# ESP — División de gastos por categoría

Especificación previa al código: 2026-11-02, America/Santiago. El usuario autoriza implementar, probar, desplegar en el servidor y actualizar el repositorio la propuesta interactiva de división. Cada parte contiene exclusivamente categoría y monto CLP; la barra ajusta importes en tiempo real. No se crea una dimensión persona.

## Contrato verificable

| ID | Comportamiento exigido |
| --- | --- |
| ESP-01 | Conservar íntegra la fila bancaria original (ID, fecha, monto, moneda, categoría previa, notas, referencias de email/Fintoc/cartola y período). El despliegue no divide, reclasifica ni reescribe ningún movimiento automáticamente. Los repartos son metadatos asociados que el usuario crea explícitamente. |
| ESP-02 | Admitir gastos positivos de tarjeta nacional (`tc_nacional`), internacional con CLP almacenado (`tc_internacional`) y cargos de cuenta corriente (`cuenta_corriente`). Excluir ingresos, pagos, desestimados y pagos de tarjeta desde cuenta corriente. Repartir el importe CLP ya guardado sin cambiar USD, tipo de cambio o cuotas. |
| ESP-03 | Guardar entre 2 y 50 partes, cada una con importe positivo exacto hasta dos decimales y categoría propia/global válida o NULL. Suma exacta igual al importe original, validada en servidor con unidades mínimas; rechazar excesos, negativos, ceros, exponentes, precisión adicional, categorías ajenas y payload desconocido. No usar aritmética binaria para validar dinero. |
| ESP-04 | Crear/editar/deshacer un reparto es una operación atómica con control optimista de versión y lock sobre el padre. `expectedVersion:0` significa sin reparto; una versión UUID opaca identifica un reparto guardado. Cada sustitución genera UUID distinto, también tras borrar/recrear, evitando actualizaciones perdidas y ABA. Un conflicto devuelve 409 sin escrituras parciales. |
| ESP-05 | Nuevas tablas `expense_splits` y `expense_split_parts`. Cabecera con owner/source, una de tres FKs reales a padres UUID, importe CLP de referencia, version UUID, actor/fechas; hijos ordenados con amount_clp/category_id. FKs de padre CASCADE para borrar realmente un gasto, categoría de parte RESTRICT para evitar perder clasificación. Guardas impiden cambiar monto, tipo, categoría, identidad/propietario y datos USD/tipo de cambio de un padre dividido; deshacer primero. Lecturas nunca escriben. |
| ESP-06 | API autenticada y espacio resuelto: GET/PUT/DELETE `/api/expense-splits/:source/:id`. Escrituras (incluido deshacer) requieren editar; lectura para miembros del hogar. Validar owner y categorías en servidor. GET `{source,id,total_clp,currency:'CLP',split:null\|{version,total_clp,parts:[{amount_clp,category_id,category_name}]}}`. PUT `{expectedVersion,parts:[{amount_clp,category_id}]}` devuelve el mismo envelope; DELETE `{expectedVersion}` devuelve split:null. IDs ajenos/inexistentes 404, datos inválidos 400, conflicto/guardas 409. |
| ESP-07 | Listas de las tres fuentes incluyen `row.split` con el mismo DTO o null, mediante consulta por lote acotada al propietario, sin N+1. El monto/categoría originales siguen en sus campos legacy. Interfaz usa las partes cuando existe split, no permite sobreescribirlo con selector de categoría simple; ofrece Editar división y Deshacer división explícitos. Al deshacer reaparece la categoría original sin reescribirla. |
| ESP-08 | Modal compartido: dos partes iniciales, categoría arriba y monto CLP editable abajo. Barra con separadores perceptibles, teclado/tacto/arrastre/clic y actualización de importes durante movimiento; escribir un importe actualiza barra y restante. Agregar parte, quitar y partes iguales preservan suma, resto de redondeo determinista. Diferencia visible, confirmación bloqueada si importes inválidos. Nunca cambiar persistencia antes de confirmar. Cancelar no escribe; guardado fallido conserva borrador y permite corregir; conflictos exigen recargar. |
| ESP-09 | Todas las consultas por categoría (evolución, totales, detalle de dashboard y análisis legacy) sustituyen el padre por sus partes cuando hay reparto. Total financiero y cantidad global de compras permanecen basados en padres, sin multiplicación por join. Repetir una categoría en varias partes suma sus importes y cuenta la compra una sola vez en esa categoría; detalle muestra importe atribuido y referencia al total original. Proyecciones y cuotas no se multiplican. |
| ESP-10 | El filtro Sin categoría detecta al menos una parte NULL; una fila con reparto completamente categorizado deja de estar pendiente aunque el padre legacy sea NULL. Filtrar por categoría encuentra partes. La fila conserva total original, muestra desglose y permite distinguir importe pendiente. Cuenta corriente mantiene sus saldos/totales bancarios intactos. Caché se invalida al guardar/deshacer y se respeta espacio, solo lectura y offline. |
| ESP-11 | Conciliación y deduplicación de email, Fintoc, Excel/CSV y cartolas siguen usando únicamente padres e identidades originales; la categoría no define si un gasto existe. Reimportar un cargo repartido no crea otro cargo ni reemplaza partes. Ambigüedades o cambios de importe real requieren revisión, sin forzar un ajuste. No ejecutar importaciones bancarias reales para verificar el despliegue. |
| ESP-12 | TDD RED observado antes de cada implementación (dinero, API/modelo/guardas, agregaciones/filtros y UI). Integración HTTP/PostgreSQL temporal prueba guardado, conflicto concurrente, permisos, preservación byte a byte y deduplicación con fixtures. Playwright local con fixtures comprueba las tres fuentes, barra en vivo, categorías, filtros, lectura, móvil/temas y cancelación. Regresión existente pertinente y build. |
| ESP-13 | Producción: snapshot privado y huellas de tablas financieras antes/después, aplicar únicamente migración nueva 037 y privilegios necesarios, publicar backend/build conservando assets anteriores, comprobar consultas y rechazo de escrituras inválidas. Cero repartos/usuarios/gastos ficticios en el hogar. Mantener sincronizaciones y respaldos actuales, no cambiar secretos ni proveedores. Confirmar servicio y repositorio en el mismo commit. |

## Evolución de requisitos

ESP-09/10 amplían la categoría única y el criterio UCF-02: para movimientos repartidos se usa exclusivamente el desglose; para movimientos sin reparto se conserva íntegro el comportamiento anterior. El esquema bancario, sus reglas de conciliación y el saldo real no cambian. La clasificación original se conserva como respaldo reversible; no se convierte en una parte adicional.
